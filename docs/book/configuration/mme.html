NextGCore Documentation

MME Configuration

The MME (Mobility Management Entity, nextgcore-mmed) is the 4G/EPS control-plane anchor of the dual 5G+4G core. It serves S1-MME toward eNBs (S1AP encoded and decoded by nextgcore-s1ap-gen, the codec generated from the TS 36.413 ASN.1; the hand-written S1AP codec was removed, #514), NAS EMM/ESM toward UEs (TS 24.301), S11 GTPv2-C toward the SGW-C, S6a Diameter toward the HSS, and optionally N26 GTPv2-C toward an AMF for EPS↔5GS interworking. The crate also carries SGsAP message handling, and SBc-AP toward a Cell Broadcast Centre when configured (see SBc-AP).

Configuration comes from a YAML file (default /etc/nextgcore/mme.yaml, -c/--config), the freeDiameter .conf that file names, a few environment variables, and four CLI flags. A missing or malformed file, or one with no mme: section, logs a warning and leaves the built-in defaults in place (src/bins/nextgcore-mmed/src/config.rs).

Honesty note: the nightly Docker E2E (EPC) job attaches a real LTE UE through nextgsim’s eNB to this MME and pings through the default bearer with 0% loss (docker/rust/epc-attach-check.sh). Dedicated bearers, handover, idle mode/paging and IPv6 PDN are not asserted there. This is the project’s own matched-simulator validation, not third-party certification.

Example configuration

From nextgcore/docker/rust/configs/epc/mme.yaml (mounted by docker-compose-epc.yml, which runs the daemon as -c /etc/nextgcore/mme.yaml at 172.24.0.5 and publishes 36412/sctp on 127.0.0.1, or on NEXTGCORE_RAN_PUBLISH_ADDR for an external eNB; abridged, the shipped file also carries a commented-out overload: block):

# NextGCore MME Configuration for Docker EPC Deployment
# Rust implementation

logger:
  file:
    path: /var/log/nextgcore/mme.log
  level: info

global:
  max:
    ue: 1024
    peer: 64

mme:
  freeDiameter: /etc/freeDiameter/mme.conf
  s1ap:
    server:
      - address: 172.24.0.5
  gtpc:
    server:
      - address: 172.24.0.5
    client:
      sgwc:
        - address: 172.24.0.3
      smf:
        - address: 172.24.0.4
  metrics:
    server:
      - address: 172.24.0.5
        port: 9090
  gummei:
    - plmn_id:
        mcc: 999
        mnc: 70
      mme_gid: 2
      mme_code: 1
  tai:
    - plmn_id:
        mcc: 999
        mnc: 70
      tac: 1
  security:
    integrity_order: [EIA2, EIA1, EIA0]
    ciphering_order: [EEA0, EEA1, EEA2]
  network_name:
    full: NextGCore
    short: Next
  mme_name: nextgcore-mme0

All keys live under mme:. Every field is optional.

Cargo feature: kernel-sctp

S1-MME runs only over native Linux kernel SCTP: mmed offers no userspace (sctp-proto) S1 backend. Built without --features kernel-sctp the daemon starts, binds nothing on 36412, and logs that S1-MME is absent, so no eNB can connect. The Docker builder (docker/rust/Dockerfile.builder) compiles mmed with the feature; it needs libsctp at build and run time and the host sctp kernel module.

SBc-AP (CBC interface)

SBc-AP (TS 29.168) carries ETWS/CMAS warnings from a Cell Broadcast Centre. The CBC establishes the SCTP association (TS 29.168 §4.1.3: port 29168, PPID 24), so the MME listens. The listener needs the kernel-sctp build.

Off by default. Without an mme.sbcap block no socket is opened. There is no default bind address, so you must configure the MME’s own address on the CBC network:

mme:
  sbcap:
    server:
      - address: 10.10.0.5   # required; only this address is bound
        port: 29168          # the default
    cbc:
      - address: 10.10.0.9   # the CBCs allowed to associate
    max_associations: 4      # the default
  • Only the first server address is bound. A wildcard (0.0.0.0, ::) is accepted but logged as a warning.
  • A block without a parsable server or without any cbc binds nothing, and logs an error.
  • Any association from an address not in cbc, or beyond max_associations, is answered with an SCTP ABORT at accept. It is counted in mme_sbcap_refused_associations_total{reason="peer"|"limit"} and logged, with the log rate-limited.
  • A message longer than 64 KiB is dropped before decode and counted in mme_sbcap_oversized_messages_total. mme_sbcap_received_total counts the PDUs handled.

Procedures:

  • Write-Replace Warning is sent to the eNBs that serve the List of TAIs, to all eNBs if the list is absent, or only to the eNB named by a Global eNB ID. The CBC’s Warning Area List (cells, TAIs or emergency areas) is forwarded as the eNB’s Warning Area List.
  • Stop Warning works the same way. Stop-All maps to Kill-all-Warning-Messages.
  • Both are answered at once:
    • “Message accepted”, with the Unknown Tracking Area List, when an eNB took the request;
    • “Tracking area not valid” when every TAI is unknown;
    • otherwise the failure cause.
  • An undecodable PDU, a request without its identifiers, or a message only the MME sends gets an ERROR INDICATION.
  • PWS restoration (TS 23.007 §15A.1.2): an eNB’s PWS RESTART INDICATION and PWS FAILURE INDICATION (TS 36.413 §8.12.3 / §8.12.4) are validated against the sender’s Global eNB ID and relayed to every CBC association as SBc-AP PWS-Restart-Indication / PWS-Failure-Indication (TS 29.168 §4.3.3E / §4.3.3F). They carry the Global eNB ID, the cells, the TAIs and the emergency areas as the eNB sent them. The CBC’s reload names the Global eNB ID, so it goes only to that eNB. The MME does not replay its own copy of the warnings. Relayed and unrelayed indications (no SBc-AP configured, no association) are counted in mme_sbcap_indications_total{result="sent"|"unsent"}.

Security. SBc-AP has no application-layer authentication. Run it on a private network, or under TS 33.210 network domain security (NDS/IP, IPsec), as for S1-MME. The cbc allowlist keeps unconfigured peers off; it is not authentication. The Helm chart, the k8s manifests and the compose files publish no port for it (no ports: or NodePort for 29168).

Not supported

  • SBc-AP: the Warning Indications (#1071). Write-Replace Warning Indication and Stop Warning Indication (TS 29.168 §4.3.3C / §4.3.3D, “if supported by the MME”) are not sent; the CBC’s “send indication” flags are accepted and not acted on. The Extended Repetition Period is clamped to the S1AP Repetition Period range (4095 s).

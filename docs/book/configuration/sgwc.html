SGW-C Configuration

The SGW-C (Serving Gateway Control plane, nextgcore-sgwcd) is the 4G/EPC control-plane half of the Serving Gateway. It terminates three interfaces, each on a real socket: S11 (GTPv2-C from the MME, UDP 2123), S5/S8-C (GTPv2-C toward the PGW-C, #52) and Sxa (PFCP toward the SGW-U, #387). S11 responses are gated on the Sxa results (#54), and the attach’s Create Session Request is relayed to the PGW over S5/S8 with a PAA (#491). It also handles Modify Bearer, Delete Session, Release Access Bearers, indirect data-forwarding tunnels, Downlink Data Notification and the bearer Commands.

Configuration is split three ways: a YAML file (default /etc/nextgcore/sgwc.yaml, -c/--config) that supplies the Sxa addresses and the advertised control-plane address, CLI flags (log level), and SGWC_* environment variables for the S11 bind, the PGW peer, the S5-C and GTP-U advertised addresses and the restart counter.

Honesty note: the nightly Docker E2E (EPC) job waits for the Sxa association from both ends and then attaches a real LTE UE whose default bearer crosses this SGW-C’s sessions with a 0%-loss ping. This is the project’s own matched-simulator validation, not third-party certification.

Example configuration

From nextgcore/docker/rust/configs/epc/sgwc.yaml (mounted read-only to /etc/nextgcore/sgwc.yaml by docker-compose-epc.yml):

# NextGCore SGW-C Configuration for Docker EPC Deployment
# Rust implementation

logger:
  file:
    path: /var/log/nextgcore/sgwc.log
  level: info

global:
  max:
    ue: 1024
    peer: 64

sgwc:
  gtpc:
    server:
      - address: 172.24.0.3
  pfcp:
    server:
      - address: 172.24.0.3
    client:
      sgwu:
        - address: 172.24.0.6

YAML parameters

Parsed by src/bins/nextgcore-sgwcd/src/config.rs. Every field is optional; a missing or malformed file logs a warning and changes nothing.

ParameterTypeDefaultDescription

sgwc.pfcp.client.sgwu[0].address / .portstring / u16127.0.0.1 / 8805The SGW-U this SGW-C associates with and provisions over Sxa. SGWC_SGWU_ADDR overrides it.
sgwc.gtpc.server[0].addressstringnoneAdvertised S11/S5-C control-plane address when the S11 socket is bound to a wildcard (the default) and SGWC_S11_ADVERTISE is unset (#482). It is not used as the GTP-U address; set SGWC_GTPU_ADVERTISE to the SGW-U’s address.

Not read: logger.* (use -l/--log-level) and global.max.*.

Clock: this NF refuses to start when the local clock reads before 2020-01-01, because its PFCP Recovery Time Stamp would be wrong. See A set clock is required for the remedy on RTC-less hosts.

Behavior notes

  • Sxa association (TS 29.244 §6.2.6, #1001):

    • The SGW-C sets up the association with its SGW-U at startup.
    • While there is no association, it retries the Association Setup every 10 s (T1 3 s, N1 2 per attempt). This covers an SGW-U that comes up later, and one that refuses the first Setup because its allowlist has not yet resolved the SGW-C’s address.
    • Once associated, it sends the SGW-U a Heartbeat Request every 10 s.
    • No Heartbeat Response after T1 x (N1 + 1) is a PFCP path failure. The association and its sessions are kept, and heartbeating continues. Setting the association up again over a path that only blinked would make a conformant SGW-U drop every session (TS 29.244 §6.2.6.2.2).
    • A newer Recovery Time Stamp means the SGW-U restarted. The stamp is carried in its Heartbeat Response and in its own Heartbeat Request. It is NTP-era seconds (TS 29.244 §8.2.65), compared as sent (#1033), and an older stamp from a reordered message is ignored. After a restart:
      • the association is set up again;
      • every established PFCP session is established again with the same CP F-SEID, F-TEIDs, PDRs and FARs. The SGW-C allocates them all, so the MME and the PGW keep their endpoints.
    • While there is no association, the SGW-C sends no PFCP session message (TS 29.244 §6.2.6.1). A Create Session Request is refused with No resources available before it is relayed to the PGW. Other S11 requests that need a PFCP session message are answered with a failure.

  • User plane path failure (TS 23.007 §20.3.4, TS 29.244 §7.4.5, #994):

    • The SGW-U reports a GTP-U path toward a remote peer as failed or recovered in a PFCP Node Report Request. The SGW-C answers it:
      • Request accepted;
      • 72 if the report is not from its associated SGW-U;
      • 66 (with the Offending IE) if the Node ID or the Node Report Type is missing;
      • 67 (with the Offending IE) if the report the Node Report Type announces is missing;
      • 69 if the request cannot be decoded.
    • On a failure, every UE whose downlink S1-U endpoint is that eNodeB has its S1-U bearers released with Release Access Bearers semantics. The FARs go to BUFF + NOCP and the EPS bearers are kept, so downlink data is buffered, notified (DDN) and the UE paged.
    • The peer stays marked failed for the maximum path failure duration, SGWC_UP_PATH_FAILURE_HOLD_SECS (default 120, at most 3600). If the path is still down when that expires, the record is dropped. A Modify Bearer that points a bearer at a failed peer inside the hold is answered, and the UE’s S1-U bearers are released at once.
    • A recovery report clears the record.
    • The optional S1-U path failure notification to the MME (cause “S1-U Path Failure”, §20.3.5) is not used, because it needs MME support (S1UN).

  • Metrics: http://127.0.0.1:9090/metrics. The port is set by SGWC_METRICS_PORT; the bind is loopback unless NEXTGCORE_METRICS_BIND is set (#837). The metrics are:

    • sgwc_up, sgwc_pfcp_associations, sgwc_ues;
    • sgwc_up_path_failures_total, sgwc_up_path_recoveries_total, sgwc_up_paths_failed;
    • sgwc_up_path_ues_released_total, sgwc_up_path_holds_expired_total.

  • No advertised GTP-U address means total session rejection. If the S11 socket is bound to a wildcard and neither SGWC_S11_ADVERTISE nor SGWC_GTPU_ADVERTISE is set, every Create Session Request is rejected with NO_RESOURCES_AVAILABLE.

  • Rejection semantics on S11 (per TS 29.274 tables cited in s11_parse.rs comments): a missing mandatory IE triggers a response with cause MANDATORY_IE_MISSING plus the offending IE type; an unknown header TEID gets CONTEXT_NOT_FOUND; Bearer Resource, Modify Bearer and Delete Bearer Commands are relayed to the PGW over S5/S8 (#606).

  • GTPv2-C reliability defaults come from Gtp2XactConfig::default() in libs/nextgcore-gtp/src/v2/xact.rs: T3-RESPONSE 3 s, N3-REQUESTS 3, responses cached for 12 s so retransmitted requests are answered identically without creating duplicate sessions. N3 exhaustion marks the peer path Failed (TS 29.274 §7.6 per code comment); a changed peer Recovery counter logs a stale-contexts warning and resets the path to Idle (TS 23.007 §18 per code comment).

  • No NRF, no session store. As an EPC NF the SGW-C has no SBI server and performs no NRF registration or heartbeat; UE/session/bearer/tunnel state is in-memory and lost on restart. Only the restart counter is persisted (SGWC_RESTART_COUNTER_FILE).

  • RUST_LOG overrides -l/--log-level when set, as in every NF.
